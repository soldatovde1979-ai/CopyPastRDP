# CopyPast — передача файлов через RDP-буфер обмена

Передача файлов любого размера между двумя ПК по RDP без зависаний, через кодирование файлов в Base64-текст и обмен JSON-пакетами через буфер обмена.

---

## 1. Проблема и принцип решения

При обычной передаче файлов через RDP (Ctrl+C / Ctrl+V) задействован системный процесс `rdpclip.exe`. На файлах размером больше 10–15 МБ он часто зависает, вылетает или теряет связь.

**Как решает проблему скрипт:**

1. Файл превращается в обычный текст (кодировка Base64). Для RDP-клиента это больше не файл, а просто текстовая строка, которую он передаёт со 100 % надёжностью.
2. Для крупных файлов текст режется на куски по 5 МБ (чанки).
3. Чтобы буфер не переполнялся, используется механизм подтверждения (ACK): отправитель кладёт 1-й кусок в буфер → приёмник забрал кусок и очистил буфер → отправитель увидел, что буфер пуст, и кладёт 2-й кусок.

## 3. Сценарии работы

В обмене всегда участвуют две стороны: **ПК-отправитель** и **ПК-приёмник**.

```
[ ПК-Отправитель ]                                   [ ПК-Приёмник ]
  Файл -> Base64-текст ---> [ Буфер обмена RDP ] ---> Слушатель (Watch) -> Файл в C:\CHANGE\IN
```

### Сценарий 1: Автоматический фоновый приём (Слушатель)

- **Где работает:** на ПК, который принимает файлы (например, на удалённом сервере).
- **Как работает:** запускается один раз при входе в систему (`Watch`) и висит в памяти. Раз в 0,4 секунды смотрит в буфер обмена.
- **Что делает:** если видит в буфере служебный маркер файла — забирает его, сохраняет в папку `C:\CHANGE\IN` и сразу очищает буфер (давая сигнал отправителю слать следующий кусок).

### Сценарий 2: Отправка «в один клик» (PackAuto)

- **Где работает:** на ПК, с которого отправляют файлы.
- **Как работает:** вы нажимаете «Отправить» на файле любого размера.
- **Что делает:**
  - файл мелкий (≤ 10 МБ) — упаковывает целиком и ждёт, пока Слушатель на том конце заберёт его и очистит буфер;
  - файл крупный (> 10 МБ) — нарезает на части по 5 МБ и передаёт по очереди, дожидаясь очистки буфера после каждой части;
  - после завершения издаёт звук и сам закрывается.

### Сценарий 3: Ручная распаковка в любую папку (UnpackTo)

- **Где работает:** на ПК-приёмнике, если там **не** запущен фоновый слушатель.
- **Как работает:** вы скопировали файл на источнике, перешли в нужную папку на приёмнике, кликнули по любой папке/файлу → Отправить → UnpackTo. Скрипт заберёт текст из буфера и восстановит файл прямо в текущую папку.

### Сценарий 4: Синхронизация папки между контурами (диск)

- **Где работает:** слушатель (`Watch`) на **обоих** контурах.
- **Как работает:** при включённой настройке `DiskSyncEnabled=1` слушатель раз в
  `SyncPollMs` мс просматривает папку синхронизации `C:\CHANGE\disk` (ключ `SyncDir`).
  Как только в ней (или в её подпапках) появляется новый файл, он отправляется
  **чанками** (существующим механизмом `FILE_CHUNK_DATA`) через буфер обмена на
  другой контур и сохраняется там **по тому же относительному пути**.
- **Защита от петель:** файл, принятый из другого контура, отмечается как
  «обработанный» и обратно не отправляется. Файлы, уже лежавшие в папке на момент
  старта слушателя, считаются синхронизированными и не отправляются.
- **Живучесть:** если слушатель на другом конце выключен, отправитель ждёт ACK не
  более `SyncAckTimeoutSec` секунд, после чего забирает свой пакет из буфера
  обратно и повторит попытку при следующем сканировании.
- **На обоих контурах путь `SyncDir` должен совпадать.**

### Сценарий 5: Сохранение RDP-сеанса (keep-alive)

- **Где работает:** слушатель на **внутреннем** контуре (удалённая машина).
- **Как работает:** при `KeepAliveMinutes=N` (N > 0) слушатель раз в N минут
  эмулирует активность — незаметно сдвигает курсор на 1 пиксель и возвращает
  обратно. Сессия считается активной и не закрывается по таймауту бездействия.
- **Как включить:** в [`setcp.ini`](setcp.ini) на внутреннем контуре поставить
  `KeepAliveMinutes=1` (по умолчанию выключено: `0`).

## 4. Режимы работы [`FileTransfer.ps1`](FileTransfer.ps1)

Все процессы зашиты в один скрипт `C:\CHANGE\FileTransfer.ps1`. Режим задаётся аргументом при запуске:

| Аргумент | Режим | Что делает скрипт |
|---|---|---|
| `Watch` | Слушатель | Бесконечный цикл ожидания данных в буфере. Сохраняет всё в `C:\CHANGE\IN` |
| `PackAuto` | Авто-отправка | Упаковывает выделенные файлы и ждёт подтверждения приёма (очистки буфера) от Watch |
| `Pack` | Быстрая отправка | Упаковывает файлы, бросает в буфер и сразу выключается (без ожидания приёма для мелких файлов) |
| `UnpackTo` | Ручной приём | Однократно считывает буфер и распаковывает файл в указанную папку |
| `Unpack` | Ручной приём | Однократно считывает буфер и распаковывает файл в папку по умолчанию `C:\CHANGE\IN` |

Без аргументов можно перетащить файлы/папки на скрипт — они будут упакованы.

Папки `C:\CHANGE\IN` и `C:\CHANGE\OUT` создаются автоматически. Журнал работы пишется в `C:\CHANGE\FileTransfer.log` (формат описан в [`SPEC.md`](SPEC.md)).

## 5. Настройка ([`setcp.ini`](setcp.ini))

Все параметры скрипта вынесены в настроечный файл [`setcp.ini`](setcp.ini), который лежит
рядом с FileTransfer.ps1 (обычно `C:\CHANGE\setcp.ini`). При его отсутствии используются
значения по умолчанию. Другой файл можно указать аргументом `-Config "путь\к\файлу.ini"`.

Структура файла:

```ini
[Settings]
ChunkThresholdMB=10        ; порог включения чанкового режима, МБ
ChunkSizeMB=5              ; размер одного чанка, МБ
WarningSizeMB=15           ; предупреждение при большом пакете, МБ
MaxLogLines=500            ; максимум строк в журнале
PollIntervalMs=400         ; интервал опроса буфера, мс
ClipRetryAttempts=10       ; попыток записи чанка в буфер
ClipRetryDelayMs=300       ; пауза между попытками, мс
RoutesEnabled=1            ; маршрутизация по маскам
RoutesOverrideUnpackTo=1   ; маски приоритетнее папки UnpackTo
DiskSyncEnabled=1          ; синхронизация папки между контурами (режим Watch)
SyncPollMs=1000            ; период сканирования папки синхронизации, мс
SyncAckTimeoutSec=60       ; таймаут ожидания ACK при синхронизации, сек
KeepAliveMinutes=0         ; эмуляция активности каждые N минут (0 — выкл)

[Paths]
InDir=C:\CHANGE\IN
OutDir=C:\CHANGE\OUT
LogFile=C:\CHANGE\FileTransfer.log
SyncDir=C:\CHANGE\disk     ; папка синхронизации (путь должен совпадать на обоих контурах)

[Routes]
; Маска имени файла = каталог назначения
sppr*.json=C:\Projects\ReportSPPR\examples
```

### Маршрутизация приёма по маскам

В секции `[Routes]` ключ — **маска имени файла** (`*` и `?`), значение — **каталог**,
куда сохранить подошедший файл. Например, файл `sppr-2026-09-02.json` при приёме
попадёт не в `C:\CHANGE\IN`, а в `C:\Projects\ReportSPPR\examples` (каталог создаётся
автоматически). Маски сверяются по порядку — первое совпадение побеждает. В путях
поддерживаются переменные окружения (`%USERPROFILE%` и т.п.).

Маршрутизация работает во всех режимах приёма: `Watch`, `Unpack`, `UnpackTo`.
Флаг `RoutesOverrideUnpackTo=0` отключает её для ручного режима `UnpackTo`
(приоритет получает выбранная пользователем папка), а `RoutesEnabled=0` — полностью.
В журнале маршрутизированный файл отмечается строкой `ROUTE:`.

## 6. Установка и ярлыки (shell:sendto)

### Шаг 1. Установка основного скрипта

[`Install.ps1`](Install.ps1) перемещает [`FileTransfer.ps1`](FileTransfer.ps1) в `C:\CHANGE`
и копирует туда [`setcp.ini`](setcp.ini) (если он лежит рядом), создаёт рабочие папки
`C:\CHANGE\IN` и `C:\CHANGE\OUT`, после чего автоматически запускает
[`CreateShortcuts.ps1`](CreateShortcuts.ps1) (если он лежит рядом).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Install.ps1
```

### Шаг 2. Ярлыки в меню «Отправить»

[`CreateShortcuts.ps1`](CreateShortcuts.ps1) создаёт ярлыки в `shell:sendto` (можно запустить
и отдельно, без установки):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File CreateShortcuts.ps1
```

| Ярлык | Команда запуска |
|---|---|
| SEND FILE | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\CHANGE\FileTransfer.ps1" Pack` |
| RECEIVE FILE | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\CHANGE\FileTransfer.ps1" UnpackTo` |
| SEND FILE (auto) | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\CHANGE\FileTransfer.ps1" PackAuto` |
| SEND FILE (no chank) | *(заготовка в скрипте — режим ещё не реализован в FileTransfer.ps1)* |

Помимо меню «Отправить» создаётся ярлык **СЛУШАТЕЛЬ** в Автозагрузке (`shell:startup`) —
фоновый приём `Watch` в скрытом окне:

`powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\CHANGE\FileTransfer.ps1" Watch`

При повторном запуске существующие ярлыки перезаписываются молча, а старые
ярлыки FileTransfer с другими именами удаляются.

## 7. Горячие клавиши ([`Hotkeys.ahk`](Hotkeys.ahk))

Скрипт AutoHotkey v2.0. При запуске показывает окно с подсказкой.

> **ВАЖНО (контуры):** [`Hotkeys.ahk`](Hotkeys.ahk) и все хоткеи работают
> **только на внешнем контуре** — машине, с которой открыт RDP-клиент.
> Внутри RDP-сессии (на внутреннем контуре) хоткеи **не срабатывают**:
> AutoHotkey перехватывает клавиши на внешнем контуре ещё до передачи в сессию.
> Слушатель `Watch` сейчас работает на внутреннем контуре; запустить его на
> внешнем контуре — не проблема (ярлык «СЛУШАТЕЛЬ» в Автозагрузке, см. раздел 6).
> Для синхронизации папок слушатель нужен на **обоих** контурах.

### Хоткеи передачи файлов (привязаны к ярлыкам SendTo)

| Сочетание | Действие |
|---|---|
| `Ctrl + Alt + C` | Запустить ярлык «Send File» (отправить файлы из `C:\CHANGE\OUT`) |
| `Ctrl + Alt + V` | Запустить ярлык «Receive File» (принять файлы в `C:\CHANGE\IN`) |

### Хоткеи исправления раскладки

| Сочетание | Действие |
|---|---|
| `Ctrl + Alt + R` | Исправить раскладку выделенного текста (EN ⇄ RU) |
| `Pause` | Исправить раскладку слова слева от курсора |
| `Ctrl + Alt + A` | Перезапуск скрипта (Reload) |
| `Ctrl + Alt + T` | Вставить быструю ссылку КТалк |

> Раскладка определяется автоматически по большинству символов в тексте
> (функции [`DetectDirection()`](Hotkeys.ahk:38) и [`SwitchLayout()`](Hotkeys.ahk:52)),
> после исправления переключается системная раскладка.

## 9. Лог-трекер ([`LogTracker.ps1`](LogTracker.ps1))

Для работы с журналом `C:\CHANGE\FileTransfer.log` есть отдельный инструмент —
[`LogTracker.ps1`](LogTracker.ps1). Он запускается с любого места и сам находит
путь к журналу (ключ `LogFile` из [`setcp.ini`](setcp.ini)).

| Команда | Что делает |
|---|---|
| `powershell -File LogTracker.ps1` | Интерактивное меню |
| `powershell -File LogTracker.ps1 -Tail 30` | Последние 30 строк |
| `powershell -File LogTracker.ps1 -Follow` | Живой режим (аналог tail -f), выход Ctrl+C |
| `powershell -File LogTracker.ps1 -Stats` | Сводка: период, режимы, события, объём данных |
| `powershell -File LogTracker.ps1 -Errors` | Только ошибки и предупреждения |
| `powershell -File LogTracker.ps1 -Filter "sppr"` | Строки, содержащие указанный текст |
| `powershell -File LogTracker.ps1 -Search "msi"` | Поиск с номерами строк журнала |
| `powershell -File LogTracker.ps1 -Clear` | Очистка журнала (с подтверждением) |
| `powershell -File LogTracker.ps1 -Log "путь\к\лог.log"` | Свой файл журнала |

В выводе трекера ошибки подсвечиваются красным, предупреждения — жёлтым,
успешные операции — зелёным.
