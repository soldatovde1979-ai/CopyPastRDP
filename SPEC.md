# SPEC — спецификация протокола данных и журнала (Data Log)

Проект: **CopyPast** — передача файлов через RDP-буфер обмена.
Основание: [`FileTransfer.ps1`](FileTransfer.ps1).

---

## 1. Обзор протокола

Файлы передаются между двумя ПК (источником и приёмником) через **RDP-буфер обмена как обычный текст**.
Файл читается побайтово, кодируется в Base64 и оборачивается в JSON-пакет с маркером.
RDP передаёт текст надёжно, поэтому исчезает ограничение `rdpclip.exe` на большие файлы.

Ключевые элементы протокола:

| Элемент | Значение |
|---|---|
| Транспорт | Буфер обмена Windows (RDP-канал) |
| Кодирование файла | Base64 |
| Обёртка | JSON (сжатый, `ConvertTo-Json -Compress`) |
| Подтверждение приёма (ACK) | Очистка буфера приёмником |
| Идентификация отправителя | Поле `Origin` = `$env:COMPUTERNAME` |
| Часовой пояс / формат времени | `yyyy-MM-dd HH:mm:ss` (локальное время ПК) |

## 3. Форматы пакетов (JSON)

### 3.1. Единый пакет — `FILE_TRANSFER_DATA`

Применяется для файлов суммарным объёмом **≤ 10 МБ** (`ChunkThresholdMB`).

```json
{
  "Files": [
    { "Name": "документ.pdf", "Content": "<Base64>" },
    { "Name": "таблица.xlsx", "Content": "<Base64>" }
  ],
  "Timestamp": "2026-09-02 17:20:00",
  "Marker": "FILE_TRANSFER_DATA",
  "Origin": "PC-OTPRAVITEL"
}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `Files` | массив объектов | да | Список передаваемых файлов |
| `Files[].Name` | string | да | Имя файла (без пути, применяется `GetFileName`) |
| `Files[].Content` | string | да | Содержимое файла в Base64 |
| `Timestamp` | string | нет | Момент упаковки, формат `yyyy-MM-dd HH:mm:ss` |
| `Marker` | string | да | Всегда `FILE_TRANSFER_DATA` |
| `Origin` | string | да | Имя ПК-отправителя (`$env:COMPUTERNAME`) |

### 3.2. Чанк крупного файла — `FILE_CHUNK_DATA`

Применяется, если суммарный объём **> 10 МБ** (`ChunkThresholdMB`).
Файл режется на части по **5 МБ** (`ChunkSizeMB`); каждый чанк — отдельный пакет.

```json
{
  "Marker": "FILE_CHUNK_DATA",
  "FileId": "3f2a9c4d1b8e4f6a9d0c7b5a2e1f8d3c",
  "Name": "видео.mp4",
  "ChunkIndex": 1,
  "TotalChunks": 4,
  "Content": "<Base64, до 5 МБ>",
  "Origin": "PC-OTPRAVITEL"
}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `Marker` | string | да | Всегда `FILE_CHUNK_DATA` |
| `FileId` | string | да | GUID файла (`Guid("N")`, 32 символа без дефисов) — объединяет чанки одного файла |
| `Name` | string | да | Имя файла (без пути) |
| `RelPath` | string | нет | Относительный путь файла внутри папки синхронизации `SyncDir` (прямые слэши `/`). Используется только в дисковом режиме синхронизации (`DiskSyncEnabled=1`, см. раздел 4.5) |
| `ChunkIndex` | int | да | Номер чанка, начиная с **1** |
| `TotalChunks` | int | да | Общее число чанков файла (`Ceiling(размер / 5 МБ)`, минимум 1) |
| `Content` | string | да | Содержимое чанка в Base64 |
| `Origin` | string | да | Имя ПК-отправителя |

> Пустой файл (0 байт): отправляется ровно один чанк (`TotalChunks = 1`, `Content = ""`).

### 3.3. Команда управления — `FILE_DISK_CMD`

Служебный пакет-команда (не файл). Отправляется режимом `ClearDisk`; слушатель на
другом контуре выполняет действие и подтверждает приём очисткой буфера (ACK).

```json
{
  "Marker": "FILE_DISK_CMD",
  "Action": "ClearDisk",
  "Origin": "PC-OTPRAVITEL"
}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `Marker` | string | да | Всегда `FILE_DISK_CMD` |
| `Action` | string | да | Действие: `ClearDisk` — удалить всё содержимое `SyncDir` (включая `change.log`), создать пустой `change.log` |
| `Origin` | string | да | Имя ПК-отправителя команды |

Приёмник обрабатывает пакет **до** распаковки файлов и отвечает очисткой буфера.
Пакет с `Origin` = имя этого же ПК игнорируется (механизм «свой-чужой», раздел 4.3).
Если ACK не получен за `SyncAckTimeoutSec` секунд, отправитель забирает пакет из
буфера обратно; локальная папка при этом остаётся очищенной.

## 4. Протокол обмена (согласование через буфер)

Буфер обмена в RDP — **один на два ПК**. Он используется и как канал данных, и как канал подтверждения.

### 4.1. Передача пакета (мелкий файл, режим `Pack` / `PackAuto`)

1. Отправитель кладёт JSON-пакет в буфер (`Clipboard.SetText`, фолбэк — `Set-Clipboard`).
2. Приёмник (Watch) обнаруживает маркер, сохраняет файл в `C:\CHANGE\IN` и **очищает буфер** (`Clipboard.Clear()`).
3. Очистка буфера — это **ACK**: для режима `PackAuto` отправитель опрашивает буфер каждые 400 мс и считает передачу завершённой, когда `ContainsText()` вернул `false`.

### 4.1.1. Ручной приём после отправки (UnpackTo)

Порядок работы привычный: сначала файл отправляется с источника, затем на приёмнике
нажимается «RECEIVE FILE» на нужной папке. Фоновый `Watch` при этом продолжает
работать как раньше и мгновенно принимает пакет в `InDir`, поэтому `UnpackTo`
действует так:

1. Если чужой пакет всё ещё лежит в буфере (слушатель выключен или не успел
   обработать) — файл принимается из буфера напрямую в выбранную папку.
2. Иначе файлы из `InDir`, записанные не позже `ManualReceiveWindowSec` секунд назад,
   перемещаются в выбранную папку (незавершённые сборки `.part` пропускаются).
3. Если ни пакета в буфере, ни свежих файлов нет — предупреждение в журнале
   (`Manual receive: ... no recent files`), файлы в `InDir` не затрагиваются.

### 4.2. Чанковый режим (> 10 МБ)

Для каждого чанка повторяется цикл:

1. Отправитель кладёт чанк `N` в буфер (до 10 попыток записи с паузой 300 мс).
2. Отправитель ждёт, пока буфер станет пустым (опрос каждые 400 мс) — приёмник забрал чанк и очистил буфер.
3. Отправитель кладёт чанк `N+1`.

Приёмник дописывает каждый чанк во временный файл `<имя>.part`, а при получении `ChunkIndex == TotalChunks` переименовывает его в `<имя>` (финальная сборка).

### 4.3. Свой-чужой (защита от «самосъедания»)

Фоновый `Watch` игнорирует пакет, если `Origin` совпадает с `$env:COMPUTERNAME` текущего ПК:
пакет был положен в буфер **этим же** ПК и предназначен для Watch на другом конце RDP.

### 4.4. Синхронизация папки между контурами (диск)

- Включается флагом `DiskSyncEnabled=1`; работает только внутри режима `Watch`.
- Папка `SyncDir` (по умолчанию `C:\CHANGE\disk`) сканируется раз в `SyncPollMs` мс
  рекурсивно. Путь `SyncDir` на обоих контурах должен совпадать.
- Новый файл (открывающийся монопольно — никто его не дописывает) отправляется
  **чанками** `FILE_CHUNK_DATA` с полем `RelPath` — относительным путём внутри
  `SyncDir` (с прямыми слэшами). Мелкие файлы тоже идут чанками (один чанк).
- Приёмник с `DiskSyncEnabled=1` сохраняет такой чанк в `SyncDir\RelPath`
  (подкаталоги создаются автоматически, сегменты `..`/`.` из пути вырезаются).
- **Маршрутизация:** маски из `[Routes]` приоритетнее `SyncDir` — если имя принятого
  файла совпало с маской, файл сохраняется в каталог маски (диск — место по умолчанию,
  в журнале — строка `SYNC-ROUTE:`).
- **Журнал `change.log`:** в корне `SyncDir` слушатель ведёт персистентный журнал.
  Формат строки: `дата-время|ТИП|относительный-путь|длина|LastWriteTimeUtc-ticks`,
  где ТИП — `SNAPSHOT` (файл был на диске при создании журнала), `SENT` (отправлен),
  `RECEIVED` (принят), `LOCKED` (был занят записью — не блокирует отправку).
- Защита от петель: принятый файл заносится в журнал как `RECEIVED` и обратно не
  отправляется; отправленный — как `SENT`. Журнал переживает перезапуск слушателя.
  Файлы, которых нет в журнале, считаются новыми и отправляются.
- При первом запуске (журнала нет) все файлы `SyncDir` помечаются `SNAPSHOT` и не
  отправляются. Журнал больше 2000 строк автоматически пересоздаётся из текущего
  содержимого папки. Сам `change.log` и файлы `.part` в синхронизации не участвуют.
- **Переотправка лежащих файлов:** команда `FileTransfer.ps1 Resend [маска...]`
  стирает записи журнала (все либо подходящие под маски) и перезапускает слушатель.
  Если журнала ещё нет — он создаётся пустым, поэтому снапшот при перезапуске
  не выполняется и **все файлы в `SyncDir` отправляются** на другой контур.
- **Полная очистка папки на обоих контурах:** команда `FileTransfer.ps1 ClearDisk`
  удаляет всё содержимое `SyncDir` локально (включая `change.log`), создаёт пустой
  `change.log`, перезапускает локального слушателя и отправляет пакет `FILE_DISK_CMD`
  (раздел 3.3) на другой контур; его слушатель выполняет ту же очистку и отвечает
  ACK. В журнале — строки `CLEAR-DISK:`. Пустой `change.log` не приводит к снапшоту,
  поэтому новые файлы продолжают синхронизироваться как обычно.
- Если ACK не получен за `SyncAckTimeoutSec` секунд (слушатель на другом конце
  выключен), отправитель очищает буфер — забирает свой пакет обратно — и повторит
  попытку при следующем сканировании.

- **Самообновление:** при `AutoUpdate=1` принятые в корень `SyncDir` файлы с именами
  `FileTransfer.ps1` и `setcp.ini` копируются в каталог запущенного скрипта
  (`Split-Path $PSCommandPath`), после чего `Watch` перезапускается — запускает новый
  процесс в скрытом окне и завершает текущий (`exit 0`). В журнале — строки `AUTOUPDATE:`.
  Файлы с такими именами во вложенных папках `SyncDir` не применяются. Файл
  `setcp.local.ini` в список автообновления **не входит** — локальные настройки
  контура не затираются.
- **Защита от двойного запуска:** при старте `Watch` останавливает другие процессы
  `powershell.exe` с командной строкой `*FileTransfer.ps1*Watch*` (кроме собственного).
- **Диагностика:** раз в `WatchHeartbeatSec` секунд пишется строка `Watch alive`
  (состояние буфера, время до ближайшего скана). При `WatchTrace=1` каждый цикл опроса
  логируется строкой `TRACE:` с причинами пропуска файлов: уже обработан, занят записью,
  не отправлен.

### 4.5. Сохранение RDP-сеанса (keep-alive)

При `KeepAliveMinutes=N` (N > 0) слушатель раз в N минут эмулирует активность:
сдвигает курсор на 1 пиксель и возвращает обратно. Сессия считается активной и
не закрывается по таймауту бездействия. Рекомендуется включать на **внутреннем**
контуре (удалённая машина), где выполняется сессия. Так как общий `setcp.ini`
синхронизируется на оба контура, включение выполняется локальной настройкой
контура: `FileTransfer.ps1 SetLocal Settings KeepAliveMinutes 1` (см. раздел 5.4) —
на внешнем контуре значение остаётся `0`.

### 4.6. Тайминги

| Операция | Период/Таймаут |
|---|---|
| Опрос буфера (Watch) | 400 мс |
| Ожидание ACK (PackAuto, чанки) | 400 мс |
| Повтор записи чанка в буфер | до 10 попыток, пауза 300 мс |
| Сканирование папки синхронизации | каждые `SyncPollMs` мс (по умолчанию 1000) |
| Ожидание ACK при синхронизации | до `SyncAckTimeoutSec` сек (по умолчанию 60) |
| Эмуляция активности (keep-alive) | каждые `KeepAliveMinutes` минут (0 — выкл) |
| Heartbeat в журнал (Watch alive) | каждые `WatchHeartbeatSec` сек (по умолчанию 60, 0 — выкл) |

## 5. Пороги и параметры (setcp.ini)

Все параметры скрипта вынесены в настроечный файл **`setcp.ini`**, который лежит рядом с
[`FileTransfer.ps1`](FileTransfer.ps1) (обычно `C:\CHANGE\setcp.ini`). Другой файл можно
указать аргументом `-Config "путь\к\файлу.ini"`. При отсутствии INI используются
значения по умолчанию из таблиц ниже.

### 5.1. Секция `[Settings]`

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `ChunkThresholdMB` | `10` | Выше — включается чанковый режим |
| `ChunkSizeMB` | `5` | Размер одного чанка |
| `WarningSizeMB` | `15` | Предупреждение в журнале при размере пакета выше порога |
| `MaxLogLines` | `500` | Максимум строк в журнале (ротация, см. раздел 8.4) |
| `PollIntervalMs` | `400` | Интервал опроса буфера, мс (Watch и ожидание ACK) |
| `ClipRetryAttempts` | `10` | Попыток записи чанка в буфер |
| `ClipRetryDelayMs` | `300` | Пауза между попытками записи, мс |
| `RoutesEnabled` | `1` | Маршрутизация приёма по маскам из `[Routes]` |
| `RoutesOverrideUnpackTo` | `1` | Маски приоритетнее каталога, выбранного вручную в `UnpackTo` |
| `ManualReceiveWindowSec` | `300` | Окно «свежести» файлов в `InDir` для режима `UnpackTo`: файлы, принятые не позже N секунд назад, переносятся в выбранную папку (см. раздел 4.1.1) |
| `DiskSyncEnabled` | `0` | Синхронизация папки `SyncDir` между контурами (режим Watch) |
| `SyncPollMs` | `1000` | Период сканирования папки синхронизации, мс |
| `SyncAckTimeoutSec` | `60` | Таймаут ожидания ACK при синхронизации, сек |
| `KeepAliveMinutes` | `0` | Эмуляция активности каждые N минут (0 — выключено) |
| `AutoUpdate` | `1` | Принятые в `SyncDir` `FileTransfer.ps1`/`setcp.ini` применяются, слушатель перезапускается |
| `WatchHeartbeatSec` | `60` | Период записи heartbeat-строки `Watch alive` в журнал, сек (0 — выключено) |
| `WatchTrace` | `0` | Подробный trace каждого цикла опроса с причинами действий (диагностика) |

Булевы флаги принимают `1`/`0`, `true`/`false`, `yes`/`no`, `on`/`off`. Любое
числовое значение трактуется как флаг: `0` — выключено, **ненулевое (в том числе
опечатка вида `DiskSyncEnabled=1000`) — включено**.

`ChunkThresholdMB` и `ChunkSizeMB` можно дополнительно переопределить аргументами
командной строки (`-ChunkThresholdMB`, `-ChunkSizeMB`) — они имеют приоритет над INI.

### 5.2. Секция `[Paths]`

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `InDir` | `C:\CHANGE\IN` | Каталог приёма по умолчанию (создаётся автоматически) |
| `OutDir` | `C:\CHANGE\OUT` | Каталог исходящих файлов |
| `LogFile` | `C:\CHANGE\FileTransfer.log` | Файл журнала |
| `SyncDir` | `C:\CHANGE\disk` | Папка синхронизации между контурами (путь должен совпадать на обоих контурах) |

В путях поддерживаются переменные окружения (`%USERPROFILE%` и т.п.).

### 5.3. Секция `[Routes]` — маршрутизация приёма по маскам

Ключ секции — **маска имени файла** (подстановочные знаки PowerShell: `*` и `?`),
значение — **каталог назначения**. Имя принимаемого файла сверяется с масками
в порядке следования; первый совпавший маршрут побеждает. Файл сохраняется в
указанный каталог (создаётся автоматически), иначе — в каталог приёма по умолчанию.

```ini
[Routes]
sppr*.json=C:\Projects\ReportSPPR\examples
report_*.xlsx=C:\Projects\Reports\Inbox
```

Маршрутизация применяется во всех режимах приёма (`Watch`, `Unpack`, `UnpackTo`).
Для `UnpackTo` её можно отключить флагом `RoutesOverrideUnpackTo=0` — тогда приоритет
получает каталог, выбранный пользователем вручную. Полностью маршрутизация
отключается флагом `RoutesEnabled=0`. В журнале маршрутизированный файл отмечается
строкой `ROUTE:`.

> Предельный размер одного пакета быстрого режима: ≤ `ChunkThresholdMB` исходных данных
> + накладные Base64 (~+33 %). Ограничение стабильности RDP.

### 5.4. Локальные настройки контура (`setcp.local.ini`)

Общий `setcp.ini` синхронизируется между контурами через `SyncDir` и перезаписывается
самообновлением, поэтому в нём нельзя хранить отличия контуров (keep-alive нужен
только на внутреннем). Для отличий служит файл `setcp.local.ini`, лежащий рядом с
основным INI (при `-Config "x.ini"` — файл `x.local.ini`):

- значения из локального файла **приоритетнее** значений общего `setcp.ini`
  (слияние выполняется при каждой загрузке конфигурации);
- локальный файл **не участвует** в синхронизации: [`Install.ps1`](Install.ps1)
  копирует в `SyncDir` только `FileTransfer.ps1` и `setcp.ini`, а самообновление
  применяет только эти два имени;
- управление без ручного редактирования (после изменения работающий слушатель
  перезапускается автоматически):

```powershell
FileTransfer.ps1 SetLocal <Секция> <Ключ> <Значение>   # записать локальную настройку
FileTransfer.ps1 DelLocal <Секция> [Ключ]              # удалить ключ или всю секцию
FileTransfer.ps1 LocalShow                             # показать итоговые настройки с пометкой (local)
```

## 6. Правила обработки на приёмнике

1. Из `Name` извлекается только имя файла ([`System.IO.Path.GetFileName()`](FileTransfer.ps1:388)) — пути отбрасываются.
2. Существующий файл **перезаписывается** (в журнале — строка `OVERWRITE`).
3. При чанковой сборке предыдущий `.part` удаляется при получении чанка `1`.
4. Некорректный JSON или неизвестный маркер — ошибка, буфер **не очищается**.
5. Перед сохранением имя файла сверяется с масками из `[Routes]` файла `setcp.ini`
   (см. раздел 5.3): при совпадении файл сохраняется в каталог маршрута, а не в каталог приёма.

## 7. Режимы работы (диспетчер аргументов)

| Аргумент | Метка в журнале | Поведение |
|---|---|---|
| `Watch` | `Watch` | Бесконечный фоновый приём в `C:\CHANGE\IN` |
| `PackAuto` | `PackAuto` | Упаковка + ожидание ACK |
| `Pack` | `Pack` | Упаковка в буфер без ожидания ACK (для мелких файлов) |
| `UnpackTo` | `UnpackTo` | Однократный приём в каталог выделенного файла/папки |
| `Unpack` | `Unpack` | Однократный приём в `C:\CHANGE\IN` |
| `SetLocal` | `SetLocal` | `SetLocal <Секция> <Ключ> <Значение>` — записать локальную настройку контура |
| `DelLocal` | `DelLocal` | `DelLocal <Секция> [Ключ]` — удалить ключ/секцию локальных настроек |
| `LocalShow` | `LocalShow` | Показать итоговые настройки (общие + локальные) |
| `Resend` | `Resend` | Очистить `change.log` (весь или по маскам) и перезапустить слушатель |
| `ClearDisk` | `ClearDisk` | Очистить `SyncDir` на обоих контурах (локально + пакет `FILE_DISK_CMD` на другой контур) |
| *(без аргумента, но с путями)* | `SendFile` | Упаковка переданных путей (drag&drop) |

## 8. Спецификация журнала (Data Log)

### 8.1. Расположение и кодировка

- Путь: `C:\CHANGE\FileTransfer.log`
- Кодировка: UTF-8
- Запись: `Add-Content` (дополнение в конец)

### 8.2. Формат строки

```
[yyyy-MM-dd HH:mm:ss] [Метка] Сообщение
```

Примеры:

```
[2026-09-02 17:20:01] [Pack] ===== START: Pack =====
[2026-09-02 17:20:01] [Pack] Packing 2 files (1.85 MB)...
[2026-09-02 17:20:02] [Pack]   [1/2] документ.pdf (1024.0 KB)
[2026-09-02 17:20:03] [Pack] OK: Sent 2 files to clipboard! (1.85 MB)
[2026-09-02 17:20:03] [Pack] ===== END: exit 0 =====
```

| Поле | Формат | Описание |
|---|---|---|
| Метка времени | `yyyy-MM-dd HH:mm:ss` | Локальное время ПК, где выполняется скрипт |
| Метка (`label`) | строка | Режим запуска: `Watch`, `Pack`, `PackAuto`, `Unpack`, `UnpackTo`, `SendFile` |

### 8.3. Сообщения (префиксы)

| Префикс/текст | Уровень | Смысл |
|---|---|---|
| `===== START: <метка> =====` | маркер | Начало сеанса |
| `===== END: exit <код> =====` | маркер | Завершение сеанса с кодом возврата |
| `OK:` | успех | Успешное действие |
| `SUCCESS:` | успех | Файл/чанк полностью передан или собран |
| `Packing ...`, `Processing ...`, `Chunk N/M sent` | info | Ход передачи |
| `Waiting for receiver ...` | info | Ожидание ACK |
| `WARNING:` | предупреждение | Риск сбоя |
| `OVERWRITE:` | предупреждение | Перезапись существующего файла |
| `SKIP:` | предупреждение | Файл пропущен |
| `FAIL:` | ошибка | Ошибка по конкретному файлу |
| `FATAL:` | критическая | Критический сбой (буфер недоступен, чанк не записан) |
| `ERROR:` | ошибка | Некорректные данные/аргументы |
| `Watch alive` | info | Heartbeat слушателя: состояние буфера, время до ближайшего скана папки (либо `disk sync DISABLED`, если синхронизация выключена) |
| `TRACE:` | debug | Подробная диагностика цикла опроса (режим `WatchTrace=1`) |
| `AUTOUPDATE:` | info | Применено самообновление / перезапуск слушателя |
| `SYNC-ROUTE:` | info | Принятый с диска файл направлен в каталог маски из `[Routes]` |
| `LOCAL:` | info | Работа с локальными настройками контура (`SetLocal` / `DelLocal` / `LocalShow`) |
| `RESEND:` | info | Переотправка: очистка записей `change.log` |
| `CLEAR-DISK:` | info | Очистка `SyncDir`: локально, отправка/приём пакета `FILE_DISK_CMD`, подтверждение ACK |
| `No files to send!`, `Clipboard is empty!` | предупреждение | Пустой ввод |

### 8.4. Ротация журнала

- При каждом запуске вызывается [`Rotate-Log`](FileTransfer.ps1:40).
- Если в журнале **больше 500 строк** — остаются только **последние 500 строк**.
- Ошибки ротации игнорируются (не влияют на работу).

### 8.5. Коды возврата

| Код | Условие |
|---|---|
| `0` | Успех (нет ошибок в сеансе) |
| `1` | В сеансе была хотя бы одна ошибка (`$script:HasError`) |

> Режим `Watch` выполняется бесконечно и код возврата не выставляет.

## 9. Ограничения и допущения

1. Транспорт — текст в буфере обмена; бинарные данные всегда Base64 (накладные расходы ~33 %).
2. Один пакет быстрого режима целиком помещается в буфер: суммарно ≤ 10 МБ исходных данных.
3. Имя приёмника/отправителя — только `COMPUTERNAME`; при совпадении имён ПК по обе стороны RDP
   механизм «свой-чужой» (раздел 4.3) не сработает корректно.
4. Чанковая сборка не проверяет `FileId` приёмником — безопасность на совести транспортного канала RDP.
5. Протокол не шифрует данные и не содержит контрольных сумм (целостность обеспечивает RDP).
6. Синхронизация папок хранит метки обработанных файлов в персистентном журнале
   `change.log` внутри `SyncDir` и переживает перезапуск слушателя. Файл, изменённый
   после отправки (другая длина или время записи), считается новым и отправляется снова.
   При самом первом запуске всё содержимое `SyncDir` помечается как синхронизированное
   (`SNAPSHOT`); чтобы разослать уже лежащие файлы, используется команда
   `FileTransfer.ps1 Resend`.
7. Локальные настройки контура (`setcp.local.ini`) имеют приоритет над общим
   `setcp.ini`, но не синхронизируются и не перезаписываются самообновлением —
   изменения в них нужно вносить командами `SetLocal`/`DelLocal` (или вручную).
8. Хоткеи AutoHotkey работают только на внешнем контуре (машина с RDP-клиентом);
   внутри RDP-сессии они не срабатывают.
